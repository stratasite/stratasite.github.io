Self-hosting Strata Server is an **Enterprise** feature. Every other plan runs on the hosted app at [app.strata.do](https://app.strata.do), so there is no server to install or operate. To start, follow the [Quick Start](/docs/getting-started/quickstart/) instead of this guide.

Enterprise customers can run Strata in their own cloud or airgapped network. The server is distributed as a private container image with a license key, both provided as part of an Enterprise agreement. To get access, [book a call](https://calendar.app.google/KjU3TdPwfVNpfuSs5) or email [sales@strata.do](mailto:sales@strata.do).

The rest of this guide is for teams that already have an Enterprise license.

## Deployment Flow

1. Start with [Choose Your Deployment Path](/docs/self-hosting/deployment-paths/)
2. Follow the selected deployment guide
3. Validate runtime health and background processing

## Runtime Architecture

Strata Server runs as a single runtime process:

- A single Strata application service handles user traffic.
- The same service handles asynchronous platform processing.

Scale by running more identical web service instances/tasks behind your load balancer.

## Core Prerequisites

| Requirement | Version / Notes |
|---|---|
| Enterprise license | Provided with your Enterprise agreement |
| Docker Engine | 24+ |
| Docker Compose | v2.20+ |
| PostgreSQL | 18 (managed or self-hosted) |
| Network | Access to DB, registry, and storage endpoints |

## Pointing the CLI at your server

The developer guide uses `https://app.strata.do` as the server URL throughout. On a self-hosted install, use your own server's URL wherever it appears: the `server:` key in `project.yml`, the `--server` flag, and the REST API base URL.
